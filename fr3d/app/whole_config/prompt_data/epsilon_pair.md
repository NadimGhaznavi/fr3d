# Explore the Epsilon Pair

Choose the combination of `epsilon.initial` and `epsilon.decay` most likely to improve the Snake agent's high score. Consider their combined effect using the JSON report of matching experiments below.

The report's `gold` is the active search baseline. If `best_gold` is present, it is the best-ever result and may differ from that baseline. Every record in `experiments` matches the current seed and all other baseline configuration fields outside the epsilon pair. All other settings, including `epsilon.minimum`, remain fixed at the active baseline.

Choose one unused pair within the supplied bounds. Continuous values have no step or rounding requirement. For continuous parameters, `experiments` contains recorded current-seed pairs. When supplied, `value_results` lists observed pairs from current-seed runs and qualifying historical runs, sorted numerically by `initial`, then `decay`. This is not a finite grid: you may choose a pair marked `UNTESTED` or propose a new, unlisted pair. For finite parameters, `value_results` lists every planned grid pair in the same order; choose a pair marked `UNTESTED`. Each entry's `results` contains matching current-seed run results or `UNTESTED`. Fr3d checks types and bounds; Snake Lab decides full configuration validity. Pairs in `experiments` have already been used and cannot be selected, regardless of status. Only completed experiments provide performance evidence. Missing scores are unavailable, not zero. Each experiment includes its run ID; match it to `gold.run_id` to identify the baseline.

When supplied, each `history` array contains high scores from completed runs with that entry's value or pair and every other gold setting matching except the seed. These runs use different seeds from current gold. Scores are sorted numerically from lowest to highest, retaining zero and repeated scores; `[]` means no qualifying history. Use these scores to guide selection. Historical scores do not mark a value or pair as tested on the current seed or change its eligibility.

The final `epsilon_pair_history` list follows the existing report fields. It includes all completed runs with available high scores, across seeds and baseline configurations, sorted numerically by `initial`, then `decay`. Each item includes its run ID, seed, score, and `other_setting_differences`: the run's values for non-epsilon-pair settings that differ from the active baseline (seed is listed separately). An empty differences object means those settings match. These broader observations provide context, but differences in other settings can explain score differences; do not attribute them solely to epsilon. This list does not change current-seed eligibility or duplicate checks.

Call `submit_epsilon_pair` with only `initial` and `decay`. Supply both values together. At least one value must differ from the baseline; either value may remain unchanged. A prose answer does not submit a pair.
